# 동시 채팅과 권한 격리

2026-11-16 구현. 각 stdio MCP 프로세스가 OS가 배정한 `127.0.0.1:0` 포트를
독립적으로 열고, 시작할 때마다 새 128-bit `clientId`를 생성합니다.
고정 8765 포트와 공유 제어 프로세스는 사용하지 않습니다.

## 연결과 사용

1. 각 Codex 채팅에서 `firefox_status`를 호출합니다. 그 채팅의 공개
   `connectionCode` (`port:clientId`)를 Firefox 확장에 입력하고 Connect를 누릅니다.
2. 확장에 표시된 전체 코드와 채팅의 코드를 대조합니다. 연결 목록에서 원하는
   채팅을 선택한 뒤 그 채팅이 사용할 탭에서 Enable current tab을 누릅니다.
3. 다른 채팅은 별도의 연결과 탭을 허용합니다. 이미 다른 채팅이 소유한 탭은
   기존 채팅의 권한을 명시적으로 철회하기 전에는 가져올 수 없습니다.
4. Revoke/Disconnect/Remove는 선택한 연결에만 적용됩니다. Disconnect all chats는
   모든 연결을 끊습니다. 목록 선택을 바꿔도 진행 중인 MCP 명령의 대상은 바뀌지 않습니다.
5. 서버를 재시작하면 새 코드를 받아 다시 연결·허용합니다. 오래된 연결은 Remove로
   지울 수 있습니다. 연결 기록은 실행 중인 확장 메모리에만 있고 최대 16개입니다.

코드는 권한을 주는 비밀 토큰이 아닙니다. 기존 256-bit bridge token은 비공개로
보관하고 확장에만 입력합니다. 서버와 확장은 역할, clientId, 매 연결의 새 challenge를
포함한 HMAC-SHA256 증명을 교환하며 토큰 원문을 WebSocket이나 MCP 결과로 보내지 않습니다.
상대 clientId와 서버 증명이 일치해야 확장이 연결을 활성화합니다. 이전 포트가 재사용돼도
다른 프로세스의 clientId를 수락하지 않습니다. 코드의 호스트는 지정할 수 없으며
1024–65535 포트와 정확한 ID 형식만 허용합니다.

동적 포트를 위해 확장 CSP의 connect-src만 `ws://127.0.0.1:*`로 변경했습니다.
스크립트 소스와 HTTP(S) 탭 허용 원칙은 동일합니다.
[Mozilla CSP 안내](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src)를
참고했고 실제 Firefox에서 인증·통신을 검증합니다.

## 격리 불변조건

- MCP 도구에는 다른 clientId, 탭 ID, 임의 URL을 선택하는 인자가 없습니다.
  한 stdio 입력은 그 프로세스의 WebSocket만 사용합니다.
- 확장은 연결별 socket/session/grant/generation/in-flight 상태를 별도 closure에 둡니다.
  요청 본문이나 팝업의 현재 선택을 보고 명령을 다른 연결에 재라우팅하지 않습니다.
- `tabOwners`는 연결과 generation을 함께 저장합니다. Enable은 첫 스크립트 주입보다
  먼저 탭을 동기적으로 예약하므로 동시에 허용을 시도해도 두 소유자가 생기지 않습니다.
- content 채널은 clientId/sessionId/grantId/documentId를 모두 검증합니다.
  다른 채팅의 snapshot, 같은 채팅의 이전 grant, 이전 문서의 명령은 거절합니다.
- 철회는 소유권을 먼저 지우고 비동기 작업과 포트를 정리합니다. 오래된 작업의
  완료/실패/연결 해제는 새 grant나 다른 채팅의 탭 소유권을 지울 수 없습니다.
- 탭 이동·닫기·페이지 연결 유실은 해당 소유자의 권한만 해제합니다. 한 MCP의 종료는
  다른 MCP의 포트나 탭에 영향을 주지 않습니다. 이미 실행한 동작을 되돌리지는 않습니다.

## 설계 선택과 보장 범위

중앙 브로커 대신 프로세스별 연결을 선택해 leader 선출, 공유 IPC 권한, 고아 daemon,
공유 토큰으로 모든 채팅을 대표하는 문제를 피했습니다. 대신 새 MCP 세션마다 코드를
수동으로 연결하는 마찰이 있습니다. 자동 발견/페어링은 이번 범위가 아닙니다.

실제 Codex 데스크톱 26.1111.21308의 같은 프로젝트 두 테스트 채팅에서 서로 다른
프로세스와 포트/ID가 생성됐습니다. **격리 단위는 stdio MCP 세션**입니다. 미래 앱이나
다른 클라이언트가 하나의 MCP 입력을 여러 채팅에 공유한다면 그 채팅들을 구분할
신뢰할 수 있는 호출자 정보가 추가로 필요합니다. 브로커만 추가해도 해결되지는 않습니다.

Firefox의 activeTab 자체는 확장 단위 권한입니다. 여기서 제공하는 채팅별 권한은
검토 가능한 확장/서버 코드가 강제하는 별도 논리 권한이며 OS 사용자나 악성 로컬
프로세스 사이의 보안 경계가 아닙니다. 토큰/프로필을 읽거나 MCP를 우회할 수 있는
다른 도구까지 격리한다고 주장하지 않습니다. 미인증 연결에는 5초 단계별 제한을 둡니다.
미인증 연결도 이 시간 동안 해당 서버의 연결 슬롯을 사용할 수 있으므로 악성 로컬
프로세스의 가용성 공격을 방어한다고 주장하지 않습니다. 연결 유실 시 권한은 즉시
철회하며, 재접속 간격은 최대 30초로 늘어납니다. ID/증명 불일치는 재시도를 중단하고
새 코드 입력을 요구합니다. 무거운 웹 앱의 백그라운드 탭 스로틀링까지 포함한 동시
처리 성능은 이번 로컬 fixture E2E에서 검증한 범위가 아닙니다.
종료된 서버의 포트가 계속 비어 있으면 재시도는 횟수 제한 없이 이어집니다.
필요 없는 항목은 Disconnect/Remove로 중단하고, 모두 끝났으면 Disconnect all을 누릅니다.

Gemini와 프로세스 공유 가능성, 탭 예약 경쟁, 포트 재사용, 철회와 연결 종료를 검토했습니다.
모든 제안을 그대로 채택하지는 않았습니다. 새 clientId를 인증에 묶고 기존 ID 재사용을
거절하므로 포트 번호 자체를 비밀이나 채팅 권한으로 취급하지 않습니다.

Firefox Codex MCP — Linux x86_64

Linux 0.4.3 stable. RPM and DEB are the primary downloads; tar.gz is the fallback.
Includes Mozilla-signed English Codex Work Tabs 0.4.2. Windows beta.3 is unchanged.
English is the default. Korean translation: INSTALL.ko.txt and README.ko.md.

Requirements: ordinary Firefox 140+ and a local Codex app or CLI you can sign in to.
Rust, Node, pairing codes, tokens and profile paths are not needed.
Snap/Flatpak Firefox, macOS and Android are not validated.
Downloads: https://github.com/nobadwordss/firefox-codex-mcp/releases/tag/v0.4.3

Recommended: RPM or DEB
1. Install the package for your distribution with its software manager.
   If no installer opens, use a terminal in the download folder:
   Fedora: sudo dnf install ./firefox-codex-mcp-0.4.3-1.x86_64.rpm
   Ubuntu/Debian: sudo apt install ./firefox-codex-mcp_0.4.3-1_amd64.deb
   This installs a system helper without changing user homes or opening Firefox.
2. Open the release's codex-work-tabs-0.4.2.xpi in ordinary Firefox.
   Confirm Continue Installation/Allow → Add. If the file is saved, use Firefox's
   Add-ons Manager → gear menu → Install Add-on From File and select that XPI.
3. As your normal user, open Codex Work Tabs → Settings → Connect Codex → Continue.
   Never run Connect with sudo. It registers this account's connection, skill and
   guidance automatically. No separate skill download or configuration editing.
   Repeat Connect for each OS account that wants it.
   If Settings cannot reach the helper, run: firefox-codex-mcp --manage
   The setup page also provides Add Codex Work Tabs to Firefox.
4. Open a new Codex chat and try:
   Open https://example.com in the browser, click Learn more, and tell me the destination page title.
   A new work tab and successful link click confirm actual browser control.
   Review tool approval requests for the web task you asked for.

Fallback: this archive, without administrator rights
1. Fully extract the archive. Do not run setup inside the archive.
2. Open a terminal in the extracted folder and run: ./install.sh
3. Choose Install connection → Continue, then Add Codex Work Tabs to Firefox.
   Confirm Firefox's prompts, then try the new Codex chat above.
   If a script opens in an editor, use the terminal command. Double-click behavior
   varies by file manager. No administrator rights are needed for this fallback.
   If an RPM/DEB is already installed, setup uses that system helper instead of
   making a competing private copy.

Everyday use
Use your ordinary Firefox and existing profile. No additional Firefox app-menu
entry or separate Codex profile is created. Open Codex Work Tabs → Settings for
Check setup and Repair. Pause and Revoke all tab access stay in the extension.
A single connected profile is selected automatically. With several, choose Use
this Firefox in the intended profile. An offline selected profile never silently
falls back to another. Existing tabs and other chats' tabs are never adopted.
In the same chat, work tabs continue across turns. Access ends on explicit
revocation, pause, 24 hours without a request, or a Firefox/helper restart.
Visible result tabs stay open. See PRIVACY.md for website-login and data scope.

Update
- RPM/DEB: install the newer local package with the software manager or the same
  dnf/apt command using its new filename. Each user runs the system helper directly.
  Settings → Reconnect Codex repairs this user's settings; it does not upgrade OS files.
- tar.gz: extract the newer archive, run ./install.sh and choose Update connection.
- Both release old work-tab access and keep Firefox open. Start a new Codex chat.
- Install a newer signed XPI separately when a release calls for it. Direct XPI
  distribution currently has no automatic extension update channel.

Disconnect and remove
- RPM/DEB: choose Settings → Disconnect Codex for each connected OS account.
  This removes that user's owned connection, skill and guidance; the system helper
  remains. Then remove the system package with the software manager, or:
  sudo dnf remove firefox-codex-mcp
  sudo apt remove firefox-codex-mcp
  DEB purge is also supported. Package removal stops running packaged helpers,
  but never edits homes. If removed before Disconnect, reinstall and disconnect,
  or use this archive's ./install.sh --uninstall to clean the user receipt.
- tar.gz: Settings → Remove connection, or ./install.sh --uninstall.
- Remove the extension separately in Firefox Add-ons Manager if desired.
- Firefox profiles, website logins, result tabs and user edits are preserved.
  Already-dispatched browser actions cannot be undone. Close old Codex chats.

Migration from an older tar.gz
Install the RPM/DEB, then use Settings → Reconnect Codex. Setup retires unchanged,
receipt-owned user binaries, native-host files and old launchers. User modifications
remain and are reported. A foreign or modified per-user Native Messaging registration
may mask the system helper and blocks migration; review it before moving it yourself.
Do not delete Firefox profiles or Codex's whole configuration folder.

Troubleshooting
- Tools missing: install/sign in to local Codex, reopen it and start a new chat.
  Setup does not require the Codex CLI to be on PATH.
- Extension paused: choose Resume in the intended Firefox profile.
- Helper absent/damaged: reinstall the RPM/DEB, or rerun the fallback's install.sh.
- Tool approval denied: use the host's allowed approval process. Setup never changes
  approval policy. First try the Codex app or interactive CLI, not codex exec.
- Recovery: firefox-codex-mcp --doctor / --repair / --uninstall for RPM/DEB;
  ./install.sh --doctor / --repair / --uninstall for the fallback.
  Installation receipts and recovery: ~/.local/state/firefox-codex-mcp/

Advanced BiDi remains a command-line compatibility option:
./install.sh --install-bidi [ABSOLUTE_PROFILE_PATH]
No debugging launcher is installed. After saving work and closing Firefox,
advanced users can run ./install.sh --launch-firefox ABSOLUTE_PROFILE_PATH.

These local RPM/DEB files do not add an automatic APT/DNF update repository.
RPM/DEB currently have no separate package/repository signature. The XPI is signed
by Mozilla. SHA256SUMS checks integrity; also review GitHub build provenance.
Automated checks are not a novice study or a fresh desktop OS installation.
See docs/first-install-linux.md, docs/linux-packages.md and docs/firefox-only-management.md.

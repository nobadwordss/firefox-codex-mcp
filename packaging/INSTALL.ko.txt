Firefox Codex MCP — Linux x86_64 (한국어 번역)

Linux 0.4.3 정식판. RPM·DEB가 기본 배포이며 tar.gz는 보조 배포입니다.
Mozilla 서명 영문 확장 Codex Work Tabs 0.4.2를 포함합니다. Windows beta.3는 변경하지 않습니다.
기본 안내와 제품 화면은 영어입니다. English: INSTALL.txt. 한국어: README.ko.md.

필요한 것: 일반 Firefox 140+와 로그인할 수 있는 로컬 Codex 앱/CLI.
Rust·Node, 연결 코드·토큰·프로필 경로 입력은 필요 없습니다.
Snap/Flatpak Firefox, macOS, Android는 검증하지 않았습니다.
다운로드: https://github.com/nobadwordss/firefox-codex-mcp/releases/tag/v0.4.3

권장: RPM 또는 DEB
1. 배포판에 맞는 파일을 받아 소프트웨어 관리자로 설치합니다.
   설치 화면이 열리지 않으면 다운로드 폴더의 터미널에서 실행하세요.
   Fedora: sudo dnf install ./firefox-codex-mcp-0.4.3-1.x86_64.rpm
   Ubuntu/Debian: sudo apt install ./firefox-codex-mcp_0.4.3-1_amd64.deb
   시스템 연결 프로그램만 설치하며 사용자 홈을 바꾸거나 Firefox를 열지 않습니다.
2. 배포 파일의 codex-work-tabs-0.4.2.xpi를 일반 Firefox에서 엽니다.
   Continue Installation/Allow → Add에 해당하는 Firefox 안내를 확인합니다.
   파일로 저장되면 부가 기능 관리자 → 톱니바퀴 → 파일에서 부가 기능 설치를 사용합니다.
3. 일반 사용자로 Codex Work Tabs → Settings → Connect Codex → Continue를 누릅니다.
   Connect는 sudo로 실행하지 않습니다. 이 계정의 연결·스킬·지침을 자동 등록합니다.
   사용할 OS 계정마다 Connect를 한 번씩 진행합니다. 별도 스킬 설치는 필요 없습니다.
   Settings가 열리지 않으면 firefox-codex-mcp --manage를 실행합니다.
   관리 화면의 Add Codex Work Tabs to Firefox로 확장을 설치할 수도 있습니다.
4. 새 Codex 채팅에서 다음처럼 요청합니다.
   https://example.com을 브라우저로 열고, Learn more 링크를 눌러 이동한 페이지 제목을 알려줘.
   새 작업 탭과 링크 클릭이 확인되면 실제 연결이 된 것입니다.
   도구 승인 요청이 나오면 자신이 요청한 작업인지 확인한 뒤 허용하세요.

관리자 권한이 없을 때: 이 압축 파일
압축을 완전히 풀고 해당 폴더의 터미널에서 ./install.sh를 실행합니다.
Install connection → Continue → Add Codex Work Tabs to Firefox를 선택하고
Firefox 안내를 확인한 뒤 새 채팅에서 위 작업을 시도합니다. 이 방식은 사용자 전용입니다.
스크립트가 편집기로 열리면 터미널 방식을 쓰세요. 파일 관리자별 더블클릭 동작은 다릅니다.
RPM/DEB가 이미 설치되어 있으면 개인 복사본 대신 시스템 연결 프로그램을 사용합니다.

일상 사용
기존 Firefox와 프로필을 그대로 사용합니다. 별도 Firefox 앱 메뉴 항목이나 전용 프로필은
만들지 않습니다. Codex Work Tabs → Settings에서 Check setup·Repair를 사용합니다.
Pause와 Revoke all tab access는 확장에 있습니다. 프로필이 여러 개면 원하는 Firefox에서
Use this Firefox를 선택합니다. 선택한 프로필이 꺼져도 다른 프로필로 자동 전환하지 않습니다.
같은 채팅은 턴 사이 작업 탭을 이어 씁니다. 명시적 철회·중지·24시간 무요청·Firefox/연결
프로그램 재시작 시 접근이 끝나며 결과 탭은 남습니다. 개인정보 범위는 PRIVACY.md 참고.

업데이트
- RPM/DEB: 소프트웨어 관리자 또는 새 파일명을 넣은 dnf/apt 명령으로 설치합니다.
  Settings → Reconnect Codex는 계정 설정 복구이며 OS 프로그램 업그레이드가 아닙니다.
- tar.gz: 새 압축 파일을 풀고 ./install.sh → Update connection을 사용합니다.
- 이전 작업 탭 접근을 해제하며 Firefox는 유지합니다. 새 Codex 채팅에서 시작하세요.
- 릴리스가 새 서명 XPI를 제공하면 Firefox에 별도로 설치합니다. 직접 배포 XPI에는
  자동 확장 업데이트 채널이 없습니다.

연결 해제와 제거
- RPM/DEB: 연결한 OS 계정마다 Settings → Disconnect Codex를 누릅니다.
  해당 계정의 소유한 연결·스킬·지침만 제거하며 시스템 프로그램은 남습니다.
  이후 소프트웨어 관리자 또는 다음 명령으로 프로그램을 제거합니다.
  sudo dnf remove firefox-codex-mcp
  sudo apt remove firefox-codex-mcp
  DEB purge도 지원합니다. 패키지 제거는 실행 중인 패키지 연결 프로그램을 중단하지만
  사용자 홈을 편집하지 않습니다. 패키지부터 제거했다면 재설치 후 Disconnect하거나
  이 압축 파일의 ./install.sh --uninstall로 계정의 남은 연결 장부를 정리하세요.
- tar.gz: Settings → Remove connection 또는 ./install.sh --uninstall.
- 확장은 Firefox 부가 기능 관리자에서 별도로 제거합니다.
- Firefox 프로필·로그인·결과 탭·사용자 수정은 보존됩니다. 기존 Codex 채팅은 닫으세요.
  이미 브라우저로 전송된 조작을 되돌리지는 못합니다.

이전 tar.gz에서 이전
RPM/DEB를 설치하고 Settings → Reconnect Codex를 선택합니다. 변경되지 않은 장부 소유의
사용자 실행 파일·native-host 파일·구형 실행기만 정리합니다. 수정한 파일은 보고하고 남깁니다.
외부 또는 수정된 개인 Native Messaging 등록이 시스템 등록을 가리면 이전을 중단합니다.
보고된 파일을 검토한 뒤 직접 옮기세요. Firefox 프로필이나 Codex 설정 폴더 전체를 지우지 마세요.

막힐 때
- 도구가 안 보임: 로컬 Codex에 로그인하고 앱을 다시 열어 새 채팅에서 요청합니다.
  설치 시 Codex CLI가 PATH에 없어도 됩니다.
- 확장 중지: 원하는 Firefox에서 Resume을 선택합니다.
- 연결 프로그램 누락·손상: RPM/DEB를 재설치하거나 보조 배포의 install.sh를 실행합니다.
- 승인 거부: 호스트가 허용한 승인 절차를 사용하세요. 설치기는 승인 정책을 바꾸지 않습니다.
- 진단·복구·연결 제거: firefox-codex-mcp --doctor / --repair / --uninstall.
  보조 배포는 ./install.sh --doctor / --repair / --uninstall.
  설치 장부·복구 위치: ~/.local/state/firefox-codex-mcp/

고급 BiDi: ./install.sh --install-bidi [프로필 절대 경로]. 디버깅 실행기는 만들지 않습니다.
작업을 저장하고 Firefox를 닫은 뒤 ./install.sh --launch-firefox 프로필_절대_경로 를 사용합니다.

로컬 RPM/DEB는 자동 APT/DNF 업데이트 저장소를 추가하지 않습니다. 현재 별도 패키지·저장소
서명은 없고 XPI만 Mozilla 서명입니다. SHA256SUMS와 GitHub 빌드 증명을 함께 확인하세요.
자동 검증은 초보자 사용성 시험이나 새 데스크톱 OS 설치 검증의 대체가 아닙니다.
자세한 안내: docs/first-install-linux.ko.md, docs/linux-packages.md, docs/firefox-only-management.md.
